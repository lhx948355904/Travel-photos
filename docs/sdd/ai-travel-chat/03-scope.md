# AI 游玩与摄影交流页：本次范围

状态：部分已确认的功能范围草案。这里的“本次”指后续实现此功能的首版；当前交付仅有规格文档，没有页面、接口或数据库变更。

## 首版包含

| 范围 | 交付内容 | 前置决定 |
| --- | --- | --- |
| 独立页面 | 访客和管理员均可使用；首页和地图页都有入口；输入、流式回答、停止/重试、结果列表、地图和照片区域；桌面与手机可用 | 服务端额度 |
| 主题边界 | 景色、游玩、摄影问题可答；无关问题委婉回绝；混合问题只处理相关部分 | 无 |
| 地点推荐 | 可包含相册地点及外部景点；为可核实候选生成推荐理由和排序，列表、地图点双向联动 | 外部地点提供方与坐标核验方式 |
| 时间相关问法 | 无地区先追问目的地或出发城市；只有出发城市再追问愿意去多远；取得符合标准的实时数据后才提供“当前适合”地点排名，并标发布时间 | 实时信号、数据来源与新鲜度标准 |
| 相关照片 | 可展示本站照片及有授权的外部照片；有图展示，无图给空态 | 外部照片提供方、许可、署名和失效规则 |
| 服务端控制 | DashScope 调用、主题约束、结构化结果核验、错误和超时处理、使用限制 | 具体模型、权限/限额 |
| 回归保护 | 保持现有 `/map` 的相册点、画廊、搜索、管理员上传/编辑/删除行为 | 无 |

## 首版不包含

- 自动新增、修改、删除相册地点或照片；AI 推荐不写入 `location`、`photo`。
- 用 AI 生成或修图来冒充实际景色照片。
- 对没有专项实时证据的花期、红叶、营业状态、票价、客流和交通余票作准确承诺；具体接入哪些实时信号仍待确认。
- 多日行程规划、订票、导航路径规划、自动预订或支付。
- 语音输入/朗读、图片上传问答、个性化画像、用户行为推荐。
- 把 `photo_embedding` 表当作已可用的语义检索服务；现有迁移仅提供表结构，实际索引和问答链路需另行实现。
- 跨会话保存或恢复对话历史；本次只保留当前页面会话。

## 已确认方向与待定边界

| 状态 | 对首版范围的影响 |
| --- | --- |
| 已确认：允许外部景点 | 需新增地点数据来源、同名消歧、坐标验证和来源标注；外部点与本站相册点保持区分 |
| 已确认：允许有授权的外部照片 | 需确定图片接口、授权、署名、缓存及失效策略；无合法图片时可展示无图地点 |
| 已确认：访客和管理员都可使用 | 需设计公开入口和服务端限流/预算；现有地点 GET 的权限规则不会自动覆盖新接口 |
| 已确认：未给城市与出发范围都追问 | 先补充目的地或出发城市；只有出发城市时再追问愿意去多远 |
| 已确认：实时数据是当前推荐的前提 | 数据源不可用或不满足时效要求时，不输出“当前适合”地点排名 |
| 已确认：DashScope、不跨次保存、双入口 | 需在服务端接入模型；首页和地图页设入口；不新增对话历史表 |
| 待确认：来源与额度细则 | 根据 [05-决策记录](05-decisions.md) 和 [数据源调研](06-source-research.md) 完成接口契约 |

实现顺序建议：先确认 [05-待确认决策](05-decisions.md)，然后锁定接口/数据契约，再做页面和服务端，最后按 [04-验收条件](04-acceptance.md) 逐项验证。
